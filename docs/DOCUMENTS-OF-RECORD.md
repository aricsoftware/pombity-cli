# Documents of record — pombity-cli

Index required by the documents-of-record standing rule (Projects/CLAUDE.md, Michael 2026-11-05): every document in this repository that describes its behavior to someone outside the code, with what it describes and which code, configuration, or decision it depends on. A session that changes a dependency updates the matching document in the same session and says so in its report; a session that adds such a document adds it here in the same commit.

- `README.md` — (the copy on npmjs.com is the one published with 0.2.0 and is behind this file on the email sender description since 2026-11-10; the current text rides the next release, by M's decision 2026-11-11) the usage document of record, with its first section written for an agent (the three commands: send, report, verify; the enforced rules: consent/STOP, quiet hours, quotas, Retry-After, verified destinations for numbers and, from 0.2.0, email addresses (P6-23), the email rules: plain text without an own domain, the one shared sender and the service-added first line naming the organization (P6-25), service-added unsubscribe, suppression; sandbox, idempotency) plus install, configuration, exit codes, and publishing; depends on the eight commands in `src/`, the default API URL `https://api.pombity.com` (P6-06), the messaging API contract and its error-code catalog, the MIT license, and the npm publish gating (v* tag + `NPM_PUBLISH_ENABLED`, trusted publishing with provenance, P6-06). The weekly `contract.yml` workflow re-validates the fixtures below against the live `/openapi/v1.json`.
- `tests/fixtures/*.json` — recorded request/response fixtures from a real local messaging host that pin the exact messaging API contract the CLI was built against (including real quota_exceeded, invalid_verification_code, and not_found refusals, secrets redacted at recording; the three `verify-*-email` fixtures were recorded from the P6-23 build, whose email form of the verified-destination endpoints is additive); depend on the messaging-service HTTP contract — re-record against a live host when that contract changes.
